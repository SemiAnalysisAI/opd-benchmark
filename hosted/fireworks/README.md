# Fireworks: hosted teacher RL, then MOPD

`campaign.py` trains one RL teacher per domain, then a fresh student on both domains by multi-teacher on-policy distillation. The shared recipe is `shared/recipe.py` (reasoning_gym `caesar_cipher` and `simple_geometry`, thinking on); unlike the self-hosted frameworks, which distill the frozen `recipe.TEACHERS`, this campaign trains its own teachers. The Fireworks settings are at the top of `campaign.py`, and the budget settings are at the top of `lifecycle.py`.

- **Billing:** the run uses the **dedicated** Training API, billed per GPU time: one four-B200 trainer plus a one-replica rollout deployment. It does not use the per-token Serverless API. All weights and checkpoints stay on Fireworks.
- **Base model:** Qwen3.5-35B-A3B, **not** the Qwen3.6 base used elsewhere, so comparisons are not same-base. Rollouts use FP8 inference and there is no router replay; the trainer-versus-sampler log-probability delta is logged.
- **Prompts:** rendered with the Qwen3.5 chat template and `enable_thinking=True`; up to 30,720 response tokens, `max_context_length` 32,768, stop at EOS. A response scores 1 only if the text after its last `</think>` holds an `<answer>` accepted by reasoning_gym.
- **Teachers:** rank-64 LoRAs trained with PPO on group-normalized rewards, with the settings of `research/rl-teachers-2026-09-24/rl.template.toml`: 32 prompts × 8 responses, LR 1e-5 (10× its full-finetuning 1e-6), no weight decay, at most 200 updates, evaluated every 25 updates on the full dev split (126 caesar_cipher, 128 simple_geometry; greedy). The targets, caesar_cipher 70% and simple_geometry 95%, are **operational goals** just below the research teachers' held-out scores (73.3% and 99.8%, sampled at temperature 1); meeting them does not show a match with `recipe.TEACHERS`. The best evaluated checkpoint is kept, even below target. The student trains 20 updates × 128 responses (64 per domain) at LR 1e-5, with teacher-minus-student token advantages. Training is synchronous (policy lag 0, within `recipe.MAX_POLICY_LAG`).
- **Single session:** the backend allows one resident LoRA session. At each MOPD update, the controller saves the student, loads each frozen teacher checkpoint to score that teacher's domain, and restores the student's weights and optimizer state before learning. That checkpoint I/O counts as teacher time.

Prerequisites: `fireworks-ai[training]==1.2.14`, `reasoning-gym==0.1.25` (installed, or its site-packages directory in `$CAMPAIGN_PYDEPS`), `FIREWORKS_API_KEY` exported (or an `api_key_profile_label` in `config/fireworks.local.json` to read it from `~/.zprofile`), the account ID (`--account`, `config/fireworks.local.json`, or `FIREWORKS_ACCOUNT_ID`), and a tokenizer info JSON (`model`, `revision`, `path`, `eos_token_id`) for the locally cached `Qwen/Qwen3.5-35B-A3B` tokenizer.

```
python hosted/fireworks/campaign.py --root NEW_RUN_ROOT --tokenizer-info TOKENIZER_JSON [--account ACCOUNT]
python hosted/fireworks/report.py RUN_ROOT      # Also runs after verified cleanup.
cd hosted/fireworks && python test_campaign.py  # No-network regressions.
```

The launch verifies the account and freezes `hosted/fireworks`, `shared` and `data` into `RUN_ROOT/source-repo/`, then runs that copy. `--teacher-config JSON` overrides the teacher `prompts`, `learning_rate`, `eval_every`, `max_steps` and `target_tolerance`; any override is a changed protocol and must be reported as one. `--resume-plan JSON` maps each domain to `{source_root, step, restore_reference, best, [prompt_offset], [complete]}`. Use `cross_job://` references, not sampler snapshots. The source run must match on account, tokenizer revision and data hashes. If the teacher batch size changed, carry `prompt_offset` over. `report.py` writes `audit.json` and `REPORT.md`, including the student protocol check (20 updates, 2,560 responses, 64 per domain each update) and the checkpoint-swap audit. A partial run is not a completed protocol.

**Cost.** Thinking at 32k is far more expensive than the previous 256-token protocol: research responses averaged about 11k (caesar_cipher) and 4k (simple_geometry) tokens, and a teacher may run 200 updates of 256 responses. The default $200 budget will very likely stop the campaign during the first teacher; set `--budget-usd` deliberately.

**Budget guard.** An independent watchdog starts before provisioning. It estimates spend from provisioning start at $117/hour (six B200s at the public $13/hour, plus 50% headroom), plus `--prior-spend-usd`. It stops the run at `--budget-usd` minus a $25 cleanup reserve (default 200, so the stop is at 175), when training ends, or when the controller dies. It then repeatedly deletes only this run's named trainer and deployment (the deployment with `ignoreChecks`) until their release is observed. This is a conservative client-side guard, **not an invoice or a provider-enforced cap**: network failures can delay cleanup, and timings do not measure GPU utilization.
